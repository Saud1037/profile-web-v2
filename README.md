# الموقع الشخصي

موقع شخصي على طراز بروفايل ديسكورد، مع لوحة تحكم مخفية تتيح لك التحكم في كل شيء: الصورة الشخصية، الغلاف، ألوان الموقع (تدرج من الأعلى للأسفل)، حسابات التواصل الاجتماعي، والمشاريع السابقة — بدون لمس الكود.

## التشغيل محليًا

1. تأكد أن لديك [Node.js](https://nodejs.org) (إصدار 18 أو أعلى).
2. من داخل مجلد المشروع:

```bash
npm install
cp .env.example .env
```

3. افتح ملف `.env` وعدّل القيم التالية **قبل** التشغيل:

   - `ADMIN_PATH` — مسار لوحة التحكم (اجعله صعب التخمين، مثال: `panel-x7k2q`).
   - `ADMIN_PASSWORD` — كلمة مرور قوية للوحة التحكم.
   - `SESSION_SECRET` — نص عشوائي طويل (لتشفير الجلسة).

4. شغّل الخادم:

```bash
npm start
```

5. افتح المتصفح على:

   - الموقع: `http://localhost:3000`
   - لوحة التحكم (المخفية): `http://localhost:3000/<ADMIN_PATH الذي اخترته>`

لوحة التحكم غير مرتبطة بأي رابط ظاهر في الموقع — من يعرف المسار فقط يستطيع الوصول إليها، وهي محمية أيضًا بكلمة مرور.

## ما يمكنك تعديله من لوحة التحكم

- **الملف الشخصي**: الصورة الشخصية، صورة الغلاف، الاسم الظاهر، حالة الاتصال، والنبذة التعريفية.
- **الألوان**: تدرج الخلفية (من الأعلى إلى الأسفل عبر 3 نقاط لونية) ولون التمييز المستخدم في الأزرار والحدود.
- **حسابات التواصل الاجتماعي**: أضف/عدّل/احذف أي عدد من الحسابات، مع اختيار أيقونة من صورك الخاصة ورابط الحساب. تظهر كأيقونات دائرية تحت الصورة الشخصية مباشرة، وتفتح الرابط عند الضغط عليها.
- **المشاريع السابقة**: أضف/عدّل/احذف مشاريع، كل مشروع له صورة وعنوان ووصف ورابط اختياري.

اضغط **"حفظ التغييرات"** بعد أي تعديل ليتم حفظه بشكل دائم.

## هيكل المشروع

```
server.js              الخادم (Express) وواجهات API
seed/                  البيانات والصور الافتراضية (تُنسخ تلقائيًا إلى storage/ أول تشغيل)
storage/               يُنشأ تلقائيًا عند التشغيل — هنا تُحفظ بياناتك الفعلية وصورك (غير موجود في المستودع)
  ├─ site-data.json
  └─ uploads/
public/index.html      الصفحة الرئيسية للزوار
public/css/             التنسيقات
public/js/              منطق الواجهة (main.js للموقع، admin.js للوحة)
views/admin.html        لوحة التحكم (تسجيل الدخول + التعديل) — غير موجودة داخل public حتى لا تُخمَّن
```

كل التعديلات والصور تُحفظ داخل مجلد `storage/` فقط. هذا مقصود: على أي استضافة سحابية حديثة (Vercel, Render, Railway...) يُعاد بناء المشروع من الصفر مع كل نشر، وأي شيء خارج هذا المجلد يُعتبر "مؤقتًا". لذلك تحتاج قرصًا دائمًا (Persistent Disk / Volume) مربوطًا بهذا المسار تحديدًا — وليس بأي مسار آخر في المشروع.

## ⚠️ لماذا فشل الرفع والحفظ سابقًا على Vercel

Vercel تُشغّل الكود كدوال Serverless: نظام الملفات فيها للقراءة فقط بالكامل تقريبًا (باستثناء `/tmp` المؤقت الذي يُمسح بين الطلبات ولا يصلح للتخزين الدائم إطلاقًا). لذلك أي تطبيق يحفظ بيانات أو صورًا في ملفات محلية (كهذا المشروع) **لا يعمل على Vercel** مهما عدّلت الأكواد الصغيرة — الحل الوحيد هناك هو استخدام قاعدة بيانات + تخزين كائنات خارجي (مثل Vercel Blob)، وهذا خارج نطاق هذا المشروع البسيط. لهذا ننشر على Render أو Railway بدلاً من ذلك، فهما يوفران قرصًا دائمًا حقيقيًا لتطبيقات Node.js العادية.

## النشر على Railway (الأسهل، فيه خطة مجانية صغيرة)

1. أنشئ حسابًا على [railway.app](https://railway.app) واربطه بمستودع GitHub الذي يحتوي هذا المشروع (أو ارفعه عبر Railway CLI).
2. أنشئ **New Project → Deploy from GitHub repo** واختر المشروع.
3. من إعدادات الخدمة (Variables) أضف:
   - `ADMIN_PATH` = مسار سري من اختيارك
   - `ADMIN_PASSWORD` = كلمة مرور قوية
   - `SESSION_SECRET` = نص عشوائي طويل
   - `STORAGE_DIR` = `/app/storage`
4. أضف **Volume** جديد (زر يمين على الخدمة → Attach Volume أو من لوحة الأوامر ⌘K): اجعل مسار التركيب (Mount Path) = `/app/storage` بالضبط (يجب أن يطابق `STORAGE_DIR` تمامًا).
5. Railway يبني وينشر تلقائيًا. افتح الرابط الذي يعطيك إياه، ثم أضف `/<ADMIN_PATH>` في نهايته للوصول للوحة التحكم.

بهذا كل تعديل وصورة ترفعها من لوحة التحكم يبقى محفوظًا بعد كل عملية نشر جديدة.

## النشر على Render (بديل، يحتاج خطة مدفوعة للقرص الدائم)

1. أنشئ حسابًا على [render.com](https://render.com) واربطه بالمستودع، ثم **New → Web Service**.
2. Build Command: `npm install` — Start Command: `npm start`.
3. أضف متغيرات البيئة نفسها المذكورة أعلاه، مع `STORAGE_DIR` = `/var/data`.
4. من صفحة الخدمة → **Disks** أضف قرصًا جديدًا، واجعل مسار التركيب (Mount Path) = `/var/data` بالضبط. **ملاحظة:** الأقراص الدائمة على Render متاحة فقط على الخطط المدفوعة (تبدأ من خطة Starter)، ولا تتوفر على الخطة المجانية.
5. بعد ربط القرص يُعاد نشر الخدمة تلقائيًا، وتصبح البيانات دائمة.

## ملاحظة عامة

لا ترفع ملف `.env` إلى أي مستودع عام — استخدم متغيرات البيئة من لوحة تحكم المنصة نفسها. وإذا نقلت المشروع لاحقًا لمنصة أخرى، فقط تأكد أن `STORAGE_DIR` يشير لمجلد مربوط بتخزين دائم فعلي على تلك المنصة.
